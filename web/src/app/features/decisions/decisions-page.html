How versioning works here

A version is not a number someone picks. It is a slice of the commit history that reads as what changed and why.

  1. Commits. Every change lands as a commit. The last paragraph of its message is a Refs: trailer naming the work item (W-NNN) and the decisions (D-NNN) behind it.
  2. Work items. When a work item closes, CHANGELOG.md records its outcome and its commits. A release (v0.0.2) gathers the items closed up to its date.
  3. Decisions and ADRs. A decision (D-NNN) is a dated entry in docs/decisions.md; one big enough to outlive its week is promoted to an ADR in docs/adr/. Each sits under the release that was current on its date.
  4. Both ways. The index docs/traceability.md links commits, work items and decisions in both directions, so you can start from a line of code or from a decision and reach the other.

Unreleased is work dated after the latest tag. The next release is cut from it.
