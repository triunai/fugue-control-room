# Failure modes (known traps and the move that defuses each)

One entry per trap we have actually hit. Format: symptom, cause, defusing move. Add an entry the turn a new trap is found (wrap-session step 5). Architecture catches are also pinned as fitness functions (`tests/Fugue.ArchTests/FitnessTests.cs`, shrink-only baselines): the fitness test is the "pin" form for structural traps; behavioural traps are pinned by a regression test.

| # | Symptom | Cause | Defusing move |
|---|---|---|---|
| 1 | Error responses come back as `application/json`, not `application/problem+json` (hit twice: once on handler failures, once on framework 400s) | A controller-level `[Produces("application/json")]` overwrites the problem content type | No `[Produces]` on controllers. `ProblemResult` builds its `ObjectResult` at execution time; `InvalidModelStateResponseFactory` and `UseStatusCodePages` also go through it. Pinned by content-type assertions in the API tests |
| 2 | Tests and the API cannot reach the compose Postgres; auth or "database does not exist" errors from `localhost:5432` | A host Postgres on 5432 shadows the container for `localhost` | Compose publishes `${POSTGRES_PORT:-5432}`; local `.env` uses 5433 and the connection string `Port=` must match (runbook 03) |
| 3 | `cannot cast type xid to bigint` in Dapper SQL | Postgres `xmin` is `xid`, which has no direct cast to `bigint` | `xmin::text::bigint` in SQL; EF projections widen the `uint` in memory. Never create `xmin` in a migration |
| 4 | "The logger is already frozen" when several `WebApplicationFactory` hosts start in one test process | A reloadable Serilog bootstrap logger is a process-wide singleton | Use a plain (non-reloadable) bootstrap logger (ai-journal, S1 choices) |
| 5 | `Fugue.slnx` fails to load or restore | `.slnx` needs SDK 9.0.200 or newer; `global.json` pins 8.0.428 | Keep `Fugue.sln`. Do not migrate to `.slnx` on .NET 8 |
| 6 | Handlers in the test assembly are not dispatched; "no handler" at runtime | The `Mediator` source generator only sees handlers in assemblies it compiles; a test-assembly handler is invisible to the generator in the app | Use a fake sender (`FakeSender`) in unit tests; real handlers are exercised through the API host |
| 7 | Build fails on NETSDK1138 (net8 out of support) because warnings are errors | .NET 8 passed end of support on 2026-11-10 and `TreatWarningsAsErrors` is on | `CheckEolTargetFramework=false` in `Directory.Build.props`, deliberately; NuGet audit stays on (D-002). Do not "fix" by upgrading without an owner call |
| 8 | `bd init` rewrites `core.hooksPath`, can add a Dolt remote and COMMITS its own config to the current branch | beads installs its own git hooks and auto-commits `.beads/` files | Run `bd init --prefix fg --non-interactive --skip-agents --skip-hooks`; then check `git log -1`, `git config core.hooksPath` (must be empty), `git remote -v`; `git reset --mixed HEAD~1` if it committed; `.beads/` is gitignored; `npx lefthook install` (D-013) |
| 9 | A tool "succeeds" with exit code 0 but did nothing (Codex after a crash, a hook runner) | Exit codes are not evidence | Read the output. `codex-gate.mjs` reads the review text and records "failed" on error-looking output |
| 10 | A parallel agent's staged files ride along in someone else's commit | `git commit` takes the whole index | Scope commits by pathspec (`git commit -- <paths>`); one worktree per write lane |
| 11 | A brief states a fact that is already false | Contracts are written from memory | The verify-the-premises clause in `agent-task-contract`; reconcile against git, not the report |
| 12 | A rule only the prompt holds gets skipped | Prompts are advisory | Make it a gate (commit-msg, pre-push, PreToolUse guard, fitness test) |
| 13 | Every endpoint returns 401 in a test host, or the host will not start | JWT options validate on start and the fallback policy requires a user | Give each test host `Auth:SigningKey` (random base64 32 bytes) via `TestAuth.Apply`; probe hosts open the fallback with `TestAuth.OpenFallback` |
| 14 | A disabled module answers 403, not 404 `module.disabled` | The permissions of a disabled module are dropped, so authorization fails first | The gate is middleware between authentication and authorization (ADR-009), never an action filter |
| 15 | A Bruno post-response script that calls a failing endpoint throws and skips the restore step | `bru.sendRequest` throws on any non-2xx | Put state changes and restores in their own requests, in order |
| 16 | Permissions look stale after a role or override change | Nothing is cached in S3, so staleness means the token is for another user or the module is off | Check `modules` (config and db), the user's `is_active`, then the effective query; do not add a cache without the S5 trigger |
| 17 | Rotating a refresh token twice at once leaves two live tokens | Read-then-write rotation races | One conditional UPDATE claims the old row; classify the failure afterwards (reuse revokes the family) |
| 18 | Every host and test without a database answers 500 after a pipeline behavior is added | The behavior injected a scoped service that needs `DbContext` in its constructor, so it was resolved for every message, queries included | Resolve audit services lazily and only for commands (`AuditBehavior` takes `IServiceProvider`); a query-only test host with no connection string is the canary (`DiagnosticsPipelineTests`) |
| 19 | `git commit -- <dir>` commits a feature without its new files, and the commit does not build | A pathspec commit takes only TRACKED paths; new files stay untracked and are left out | `git add -- <paths>` first, then `git commit -- <paths>` (or amend); check `git show --stat HEAD` for the `A` lines |
| 20 | An audit row shows `api/v1/Customers` but the route is lower-case | `[Route("api/v1/[controller]")]` expands with the class name's casing, and `LowercaseUrls` only changes generated links | Normalise the template with `ToLowerInvariant()` when storing it (`HttpAuditRequestInfo`) |
| 21 | A scaffolded migration for a new `xmin` concurrency token contains `AddColumn xmin` and looks like it would fail | Npgsql scaffolds the token as a column but its SQL generator emits NO DDL for the system column | Read the idempotent script: only the history row should appear. Keep the migration (the snapshot must match the model), say so in the catalog row, and pin it with a throwaway-container test. Never hand-write `ADD COLUMN xmin` |
| 22 | `git commit` or a test commit script dies on `body's lines must not be longer than 100 characters`, or a scope the commitlint config does not list | commitlint enforces `body-max-line-length` 100 and a fixed scope enum (see `commitlint.config.cjs`) | Hard-wrap body paragraphs at about 95 columns and use a listed scope (`persistence`, `api`, `identity`, `docs`, `spine`, ...) |
| 23 | The Docker daemon stops answering mid-suite (`docker ps` hangs) right after the delivery and sink tests were added | Suspected, not proven (the daemon was restarted before it could be inspected): several throwaway Postgres containers plus the shared fixture and per-test stub HTTP listeners all ran in parallel. A re-run of the same tests after a restart passed, so treat it as load, not a code bug | Webhook tests share the one `PostgresFixture` collection (no container per test), every stub receiver is disposed (`await using`), new classes run alone first with `--filter` under `perl -e 'alarm 600'`, and `docker ps` is probed (`alarm 20`) before a run; if it hangs, stop and restart the runtime rather than looping |
| 24 | Every dispatcher cycle throws `A parameterless default constructor or one matching signature ... is required` | Dapper maps a positional record by exact column type, and Npgsql returns `timestamptz` as `DateTime`, so a `DateTimeOffset` constructor parameter never matches | Project into a record with `DateTime` and convert in a method (`ClaimedMessage.ToEvent`); run any new Dapper projection once before building tests on it |
| 25 | Logging in starts answering 429 during repeated Bruno or runbook runs | The login limiter (D-034) is per (IP, email) and in memory, and a full collection logs in more than once | Wait out the window or restart the API between full runs |
| 26 | Most of `Fugue.Tests` fails within seconds with `DockerUnavailableException` / `connect: no such file or directory` on `~/.orbstack/run/docker.sock` | OrbStack is not running (after a reboot or quit), so the socket file does not exist; it is not a code failure | `open -a OrbStack`, wait until `docker ps` answers, re-run. A 6-second full run with hundreds of failures is the tell |
| 27 | `codex exec` prints "Reading additional input from stdin..." and never answers; a wrapper with `alarm` kills it but the shell still reports exit 0 | Without a TTY, `codex exec` waits for stdin to close before starting | Always pass `< /dev/null` and `-o <file>` for the final message; read the output file, never trust the wrapper's exit code |
| 28 | A webhook delivery to the dev sink stays `pending` when Bruno runs against the Docker stack | The subscription URL used `{{baseUrl}}` (the host port 5081), which inside the API container points at nothing (the container listens on 8080) | Use the `compose` Bruno environment (`sinkUrl` is the container's own `http://localhost:8080/...`); `npm run api:test:compose` |
| 29 | A rule file says one thing and the code another (CLAUDE.md said Argon2id; the code uses PBKDF2 via `PasswordHasher<T>`) | Wording written at planning time, never re-checked | When a doc writer verifies claims against code, fix the rule file in the same session; grep rule files for security claims at wrap |
| 30 | Two lanes in one worktree: `pkill -f Fugue.Api` from one lane stopped every host API, including the lead's and a sibling lane's | A process pattern matches all lanes' processes, not just your own | Stop your own process by its listening port (`lsof -tiTCP:<port> -sTCP:LISTEN \| xargs kill`), never by name, when lanes share a machine |
| 31 | `git commit --amend --no-edit` after a failed commit folded one lane's staged files into another lane's commit | In a shared worktree HEAD may be someone else's commit; amend rewrites whatever HEAD is | Never amend in a shared worktree; after a failed commit fix the message and commit again. Undo with `git reset --soft <original sha>` and check the reflog |
